## Phase 27 TSDoc 规范

API 函数格式：
```typescript
/**
 * 获取用户列表。
 * @param params 查询参数（分页 + 筛选条件）
 */
export function getUsers(params: UserQuery): Promise<PageResult<UserVO>>
```

Pinia Store 职责使用 `/** */` 或 `//` 行注释：
```typescript
// 用户认证状态管理。
// 管理 JWT token 的存储、刷新和用户会话信息。
// 应用启动时自动从 localStorage 恢复登录状态。
export const useAuthStore = defineStore('auth', () => { ... })
```

Router 路由行注释：
```typescript
// 用户管理页面（需要 ADMIN 角色）
path: '/system/users',
component: () => import('@/views/system/users/UserListPage.vue'),
meta: { roles: ['ADMIN'] },
```

    - 对于没有 JSDoc 的导出的函数，添加完整 JSDoc 块（函数说明 + @param + @return）
    - 非导出内部函数/辅助函数使用行注释或不添加注释
    - @param 标签格式：`@param paramName 参数说明`

    **各模块处理要点：**

    **auth.ts**（已有 JSDoc）：
    - `login(data)`：添加 `@param data 登录参数（用户名和密码）` + `@return 登录结果（token、refreshToken 和用户信息）`
    - `refreshToken(refreshToken)`：添加 `@param refreshToken 刷新令牌字符串` + `@return 新的 token 和 refreshToken`
    - `logout()`：添加 `@return 登出结果`
    - `getCurrentUser()`：添加 `@return 当前登录用户信息`

    **user.ts、role.ts、menu.ts**（CRUD 模式的 API 文件）：
    - 每个导出函数补全 JSDoc，典型模式：
      - `getUsers(params)` → `/** 获取用户列表。\n * @param params 查询参数\n * @return 用户分页结果 */`
      - `getUser(id)` → `/** 根据 ID 获取用户详情。\n * @param id 用户 ID\n * @return 用户详情 DTO */`
      - `createUser(data)` → `/** 创建新用户。\n * @param data 用户创建参数\n * @return 创建后的用户信息 */`
      - `updateUser(id, data)` → `/** 更新用户信息。\n * @param id 用户 ID\n * @param data 用户更新参数\n * @return 更新后的用户信息 */`
      - `deleteUser(id)` → `/** 删除用户。\n * @param id 用户 ID */`

    **seckill.ts、order.ts、cart.ts、goods.ts**（业务域 API）：
    - 为每个导出函数补全 JSDoc
    - 复杂函数（如 `seckill()`、`preheat()`）的方法说明需包含业务语义

    **audit.ts、monitor.ts、knowledge.ts、rocketmq.ts**：
    - 为每个导出的函数补全 JSDoc
    - 函数说明根据 API 端点名称推断业务语义

    **goods.ts**：注意此文件可能是秒杀商品 API，按 seckill goods 的语义添加 JSDoc

    说明（遵循 D-07 决策）：
    - JSDoc 块格式：`/** 函数说明。\n * @param name 说明\n * @return 说明 */`
    - @param 和 @return 描述使用中文，技术术语（token、DTO、VO、Page 等）保留英文
    - 对返回泛型类型（如 `Promise<ApiResponse<T>>`），@return 描述 T 的业务语义而非 HTTP 封装
