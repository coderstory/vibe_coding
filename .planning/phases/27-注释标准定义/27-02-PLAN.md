  <action>
  1. 执行全局 TODO 搜索：

  ```bash
  # 后端 Java 文件
  grep -rn "TODO" springboot/src/ --include="*.java" 2>/dev/null | grep -v "/test/" | grep -v ".class" | sort

  # 前端 TS/Vue/JS 文件
  grep -rn "TODO" app-vue/src/ --include="*.ts" --include="*.vue" --include="*.js" 2>/dev/null | sort
  ```

  2. 对每个搜索结果，按以下标准分类：

  | 类别 | 定义 | 处理方式 |
  |------|------|----------|
  | A — 有效 TODO + 已有 Issue 引用 | 含 `TODO(#数字):` 格式的 TODO，内容仍有效 | 保留，无需更新 |
  | B — 有效 TODO + 无 Issue | TODO 描述的改进项/功能仍未完成，内容有效 | 生成 Issue 号并更新 |
  | C — 已完成/过期 TODO | 描述的改进已经完成，或代码已变更不再适用 | 直接删除该 TODO 注释行 |
  | D — 含义不明确 | 描述太模糊，无法判断有效性 | 标记为待确认，在报告中列出 |

  3. 生成处理报告文件 `.planning/phases/27-注释标准定义/27-02-TODO-REPORT.md`（暂存，Task 2 更新最终状态），包含：
     - 搜索范围说明
     - 按类别分组的完整 TODO 列表（含文件路径、行号、原文、分类结果）
     - 处理计划说明
  </action>

  - CLAUDE.md（格式化参考）
  </read_first>
  <action>
  根据 Task 1 的报告，逐一处理：

  **对 B 类 TODO（有效 + 无 Issue 引用）：**
  1. 为每个 B 类 TODO 创建一个唯一的 Issue 引用号。由于当前项目可能未启用 GitHub Issues，使用顺序占位编号 `#TODO-N`（N 从 1 开始递增）。格式示例：
     ```java
     // 原文：// TODO: 实现指数退避重试逻辑
     // 更新为：// TODO(#TODO-1): 实现指数退避重试逻辑
     ```
  2. 更新后多行 TODO 保持缩进风格：
     ```java
     // TODO(#TODO-1): 实现指数退避重试逻辑
     //  当前在 RocketMQ 消费失败时直接抛出异常，
     //  需要改为 ExponentialBackOff 策略提高成功率。
     ```

  **对 C 类 TODO（已完成/过期）：**
  1. 以最小 diff 删除该 TODO 注释行（仅删除注释行本身，不删除下方代码）
  2. 如果 TODO 是多行的，完整删除该注释块
  3. 不要删除 TODO 附近的其他注释

  **对 A 类 TODO（已有 Issue 引用）：**
  1. 保留不变

  **对 D 类 TODO（含义不明确）：**
  1. 保留原文不变
  2. 在报告文件中标记为"待确认"

  每次修改后执行编译验证（仅对 Java 文件修改后）：
  ```bash
  ./gradlew.bat build -x test
  ```

  前端文件修改后执行：
  ```bash
  cd app-vue && npx vue-tsc --noEmit 2>&1 | head -20
  ```
  </action>
